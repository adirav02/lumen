## Repaired behavior

| Area | Reproduced failure | Repair and regression evidence |
|---|---|---|
| Backup safety | A directory destination equal to the workspace, its ancestor, or originals could replace live data | Reject protected/overlapping destinations before backup publication; reject database/staging targets too |
| Restore portability/layout | Windows drive paths were accepted on POSIX; database assets outside the restored originals layout could be validated but omitted | Reject Windows drive/UNC paths on every platform and reject source paths outside the originals layout |
| Transaction rollback | Exercise-version failure left an orphan exercise; a non-idempotent response serialization error left a committed mutation | Parent/version writes and response validation remain inside atomic transactions, with or without request IDs |
| Course boundaries | Parent topics, aliases, links, exercise mappings, and evaluated evidence could reference another course; invalid evidence could end in an internal exception | Validate topic ownership at public write boundaries and reject/roll back cross-course writes |
| Retrieval scope | `source_id` was ignored; topic filtering happened after the result limit | Apply source/topic filters inside FTS and fallback queries before limiting; constrain alias hits too |
| Retrieval ambiguity | Reading by a duplicate title without dependency expansion silently selected one unit | Reject ambiguous titles and require exact unit identity |
| Source integrity | Missing originals were reported as present; a corrupt existing original was silently reused | Separate file existence from hash verification and verify stored bytes before reuse |
| Source deduplication | The same bytes under several logical sources could create duplicate versions when an earlier source was re-ingested | Scope hash reuse to the logical source |
| Unicode identity | Two exercise-hash implementations encoded Hebrew differently, hiding valid resumable work | Share one canonical implementation while preserving the historical runtime hash encoding |
| Diagnostic points/ownership | Items always had a 10-point denominator; CLI discarded an explicit assessment learner | Use finite positive rubric maxima and forward the asserted owner |
| Evidence exposure | Starting a new attempt forgot prior same-family hints/solutions | Carry earlier same-learner/family assistance into evaluation and correction, bounded by submission time |
| Independent evidence diversity | Repeated family/skill/subpart observations inflated fresh independent counts | Projection policy 2 counts distinct learner/family/skill/subpart keys; preserves raw observations and their count separately |
| Evidence input | String `"false"` could complete an attempt; contradictory correctness/mastery could create positive evidence | Require a boolean completion flag and reject contradictory evaluated levels |
| Preferences | Stored preference repository had no public save operation; course language did not initialize the learner preference | Add idempotent `update-learner-settings` API/CLI and inherit course language for new settings |
| Authoring retries | Several authoring commands silently ignored stable request IDs | Add transactional receipts/replay/conflict behavior to topic creation/alias/link, exercise creation, enrichment, validation, and revision updates |
| Extraction | Images and unsupported binary files could become clean gibberish text; slide tables were dropped; visual regions could look fully extracted | Preserve unsupported/visual originals with limitations; extract PPTX tables/groups and flag unreviewed visual elements |
| Publication | `publish=False` enrichment still defaulted to published | Keep enriched units pending when publication is disabled; require a boolean publication flag |
| Capability probes | Writable-check probe overwrote a fixed filename; merely importing an OCR package advertised unimplemented OCR | Use an isolated temporary probe; report core OCR as unavailable; avoid opening a core session just to inspect CLI capabilities |
| Agent workflow | Canonical skill validation example omitted checks and diagnostic selection omitted question IDs | Correct the canonical skill examples and route to `docs/lumen-workflow.md`; applied patch retained for review |

## Independent course walkthrough

Fixtures include a syllabus, Hebrew/English conditioning and independence notes, Bayes lecture revisions, a two-page PDF, a two-slide PPTX, five reviewed questions with 4/6-point rubrics, and one deliberately contradictory question candidate. All are labeled synthetic/generated.

The parent workflow executes **98 CLI invocations**, each in a fresh process:

1. Inspect capabilities, create course with retry/conflict checks, register topics and aliases, and save learner preferences.
2. Ingest five sources, inspect actual PDF pages/slide text, verify originals against input bytes, enrich a reviewed conditional-probability unit, and retrieve Hebrew aliases with exact provenance and assumptions.
3. Preserve quoted malicious document instructions as task data. No grades or instructions are taken from that quoted sentence. Keep random variables visibly missing and unassessed.
4. Create generated questions, attest exact revisions, reject the contradictory candidate, and select five checked questions for a diagnostic.
5. Submit/evaluate Bayes subpart (a), exercise idempotency/conflicts and partial scoring, pause, and resume the same linked attempt in another process.
6. Give a subpart (b) hint, preserve earlier independent work, complete (c), correct an intentionally wrong tutor judgment, invalidate the earlier score with retained history, and re-score.
7. Complete other questions with arithmetic partial progress and prior solution exposure. Verify **23/24 observed rubric points** with the RV topic still unassessed. This synthetic diagnostic result is not a pass prediction.
8. Ingest source revision 2 while resolving revision-1 bytes, explicitly revise an exercise, reject stale resume, and reopen its scored diagnostic for review.
9. Backup and restore into a moved workspace. Resolve all six source versions byte-for-byte, preserve preferences, and reject accidental restore over a populated target.

The test writes a JSON call transcript into its pytest temporary directory for inspection. It is a reproducible CLI/core workflow, not an autonomous model teaching benchmark.
