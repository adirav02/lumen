## 1. Verification Categorization & Precedence

1. **Provenance Chain & Scoring Invariants Repaired (M10)**:
   - `INV-07`: Full provenance chain eligibility (evidence record, attempt, committed submission, learner ownership, current exercise version).
   - `INV-08`: Historical score revalidation via Migration 008 against complete current policy with backups (`backup_v7_*`), quarantine to `pending_review`, and reopened assessments.
   - `INV-09`: Rebuild affected `topic_state` projections inside the migration transaction using the shared eligibility policy.
   - `INV-10`: Strict boolean `allow_partial`; reject full credit when required subparts missing; enforce consistent zero-score rule (evaluated incorrect work required; reject zero when all evidence is positive).
   - `INV-11`: Educational identity checks in `resume_attempt` (API and CLI); `course_brief` does not recommend resuming stale attempts or pair old work with replacement question text.
   - `INV-12`: Finite JSON validation before commit; recursive rejection of NaN, Inf, exponent overflow before mutations; test response serialization (`allow_nan=False`) before committing receipts.
2. **Underlying Invariants Repaired (M9)**:
   - `INV-01`: Legacy NULL identity resolution & quarantine via Migration 007 and commit rejection.
   - `INV-02`: Correction cannot revive obsolete evidence to active status; topic states, briefs, and reports exclude obsolete evidence.
   - `INV-03`: Observation evidence does not count as assessed topic coverage.
   - `INV-04`: Incomplete subpart evaluation cannot complete question; requires all required subparts or `allow_partial=True` for `partially_scored`.
   - `INV-05`: Stale legacy repair rejected with `ConflictError`; `expected_link_states` enforced.
   - `INV-06`: Non-finite values rejected in verification checks, nested metadata, and CLI input/output.
2. **Confirmed Defects Reproduced by Codex**:
   - `DEFECT-A`: Zero score accepted without evaluated evidence.
   - `DEFECT-B`: Validation approves concurrently edited question/solution/rubric.
   - `DEFECT-C`: Reaffirming unchanged attempt link erases valid score and reopens assessment.
   - `DEFECT-D`: Migration fails on legacy schema-v4 workspace containing duplicate attempt links.
   - `DEFECT-01` to `DEFECT-09`: Nine confirmed reliability and security defects.
3. **Existing Regression Cases (Must Keep Passing)**:
   - `REG-01`: Multi-connection scoring vs retraction serialization (M6 Defect 1 / F31).
   - `REG-02`: Unlinked diagnostic item scoring rejection & attempt exclusivity index (M6 Defect 2 / F32).
   - `REG-03`: Strict check schema validation (rejecting 'false', 'failed', 'pending', numbers) (M6 Defect 3 / F33).
   - `REG-04`: Timeline assistance preservation (earlier submission remains independent) (M6 Defect 4 / F34).
   - `REG-05`: Atomic assessment item startup preserving unowned assessments on error (M6 Defect 5 / F35).
   - `REG-06`: Exception-safe `LumenCore` init with zero lock/FD leaks and clean restore (M6 Defect 6 / F36).
   - `REG-F01-F30`: Storage, ingestion, retrieval, tutoring, backup/restore, and CLI failure fixtures.
3. **Additional Boundary & Lifecycle Risks Investigated**:
   - `RISK-01`: Assessment lifecycle parameter boundaries (invalid item orders: bool, float, str, <=0; blank learner IDs).
   - `RISK-02`: Cross-course boundaries on diagnostic blueprints and selected exercise versions.
   - `RISK-03`: Duplicate exercise versions in assessment creation.
   - `RISK-04`: Optimistic concurrency with `expected_revision` on `update_exercise_version`.
   - `RISK-05`: Preserved pre-migration backup table (`backup_v4_assessment_items`) during legacy migration.
4. **Three-Host Conformance & Smoke Tests (M5)**:
   - `HOST-01`: Instruction discovery and native loader integrity across Antigravity, Codex, and Claude Code.
   - `HOST-02`: Host capability detection across environment markers (`ANTIGRAVITY`, `CODEX`, `CLAUDE_CODE`, `generic_cli`).
   - `HOST-03`: Sequential multi-host workspace handover and resume smoke test across all three hosts.
   - `HOST-04`: Multi-host CLI invocation conformance across environments.
5. **Deferred Product Features (Out of Current Scope)**:
   - Live multi-device synchronization (deferred).
   - Custom graphical chat client (deferred).
   - Hosted multi-user service / fleet (deferred).
   - OCR for scans without text layers (flagged with limitation, deferred).
   - Calibrated pass prediction probabilities (deferred).
